# MSV Analysis Suite: Testing Metacognitive Inefficiency in Reasoning LLMs

This directory contains a seven-script analysis pipeline that consumes the Kaggle Benchmark outputs from the MSV research group's benchmark runs and produces the statistical evidence, tables, and figures needed to test the metacognitive inefficiency hypothesis for reasoning-enhanced LLMs. The analysis takes no new model calls: everything is computed from per-task CSVs and per-run JSON logs that Kaggle already saved during the original benchmark runs.

## What this suite tests

The central hypothesis is that **reasoning-enhanced LLMs exhibit metacognitive inefficiency**: they can solve hard tasks at or above the level of comparable non-reasoning models, but their confidence ratings and routing decisions carry little predictive information about their own per-item correctness. This manifests in three independently measurable ways across our 11 MSV benchmark tasks:

- **Task 11 (MC Binary Pairs).** Object-level discrimination `d_hat` can be large while metacognitive discrimination `type-2 AUC` remains at chance (0.5). The ratio MC = `d*` / `d_hat` approaches zero.
- **Task 1 (Delegate Game).** Delegation rates are flat across difficulty levels instead of rising with difficulty. Reasoning models answer rather than defer even on items they are likely to miss.
- **Task 2 (Declared MSV Probe).** Declared self-reports are well-differentiated across questions, but the model routes almost exclusively to ANSWER regardless of the declared activation. The self-report does not translate into routing action.

A fourth signal, **verbose chain-of-thought (CoT) emission**, operates as a behavioral signature that cleanly distinguishes reasoning models from non-reasoning models on our benchmark even before any metacognitive analysis. Scripts 1 and 6 measure this signature and test whether it correlates with the metacognitive signals.

Scripts 0–4 compute the per-signal evidence. Script 5 integrates the signals into a single cross-task convergence matrix. Script 6 tests whether verbosity and metacognitive inefficiency are one phenomenon or two.

## Directory structure and file layout

The suite expects the following structure rooted at whatever directory you are analyzing:

```
msv_analysis/
├── scripts/                        # All seven scripts + orchestrator
│   ├── script_0_catalog.py
│   ├── script_1_verbosity.py
│   ├── script_2_task11_metacog.py
│   ├── script_3_task1_delegation.py
│   ├── script_4_task2_coherence.py
│   ├── script_5_convergence.py
│   ├── script_6_verbosity_vs_efficiency.py
│   └── run_all.py                  # Orchestrator
├── data/
│   ├── kaggle_runs/                # *.run.json files from Kaggle
│   └── kaggle_csvs/                # tXX_*_results*.csv from Kaggle
└── outputs/                        # Generated by scripts; safe to delete
```

### Expected input filenames

**Run files** must match the pattern:
```
tXX-msv_<task_name>-run_id_Run_N_<provider>_<model_slug>.run.json
```
Examples:
- `t01-msv_delegate_game-run_id_Run_1_anthropic_claude-haiku-4-5-20251001.run.json`
- `t11-msv_mc_binary_pairs-run_id_Run_1_zai_glm-5.run.json`
- `t02-msv_declared_probe-run_id_Run_1_google_gemini-2.5-flash.run.json`

These files are downloaded directly from the Kaggle notebook outputs. Kaggle writes them with that naming convention automatically.

**CSV files** must match the pattern:
```
tXX_<task_shortname>_results_<model_slug>.csv
```
Examples:
- `t01_delegate_game_results_claude-haiku-4-5-20251001.csv`
- `t11_mc_binary_pairs_results_glm-5.csv`

Note: Kaggle saves these as `tXX_*_results.csv` without the model suffix, because each notebook run produces only one model's CSV. When downloading outputs from multiple models you need to rename them with the model slug before copying into `data/kaggle_csvs/`. A simple rename script:

```bash
# Example for Claude Haiku; adapt model slug as needed
mv t01_delegate_game_results.csv \
   t01_delegate_game_results_claude-haiku-4-5-20251001.csv
```

The catalog step (Script 0) uses regexes to extract model slug and task ID from filenames, so renaming is the one manual step before running the pipeline.

## Installation and dependencies

The suite targets **Python 3.10+**. Minimal dependencies:

```
pandas>=1.5
numpy>=1.24
scipy>=1.10
matplotlib>=3.7
```

Quick install:

```bash
pip install pandas numpy scipy matplotlib
```

No other packages are used. Everything else (SDT math, bootstrap, heatmaps) is implemented directly from the above libraries for maximum reproducibility and minimum supply-chain risk.

## Quickstart

1. Place your Kaggle run files in `data/kaggle_runs/` and your per-question CSVs in `data/kaggle_csvs/`. Rename CSVs to include the model slug (see above).
2. From the `scripts/` directory, run the orchestrator:

```bash
cd scripts
python run_all.py --data-root ../data --output-root ../outputs
```

The orchestrator runs all seven scripts in dependency order and prints a final summary marking each step as OK or FAILED. Individual steps that fail do not block subsequent steps that do not depend on them.

3. When the orchestrator finishes, inspect `../outputs/`. Every script writes both a CSV (human-readable numbers) and a PNG figure (for direct inclusion in the NeurIPS paper).

If you want to run a single script in isolation, invoke it directly; each has `--help` describing its arguments.

## Script-by-script reference

### Script 0: `script_0_catalog.py`

**Purpose.** Builds the central manifest CSV that every downstream script uses. Walks `data/kaggle_runs/` and `data/kaggle_csvs/`, extracts model and task IDs from filenames, reads each run file to count requests, and joins the run and CSV paths into one table.

**Inputs.**
- `--run-dir <dir>`: directory of `*.run.json` files.
- `--csv-dir <dir>`: directory of `*_results*.csv` files.
- `--out <path>`: where to write `run_catalog.csv`.

**Outputs.** A CSV with one row per (model, task) pair and these columns:

| column | meaning |
|---|---|
| `model` | model slug extracted from filename |
| `provider` | provider prefix (google, anthropic, zai, ...) |
| `task_id` | `t01`, `t02`, ..., `t11` |
| `task_name` | human-readable task name |
| `n_requests` | total prompts sent in this run |
| `n_expected` | total prompts this task was supposed to send (80 or 160) |
| `completion_rate` | `n_requests / n_expected` |
| `run_file_path` | absolute path to the `.run.json` |
| `csv_file_path` | absolute path to the per-question CSV, if matched |
| `is_reasoning` | boolean, hand-labeled in `REASONING_MODELS` set |

**Customization.** The `REASONING_MODELS` set at the top of the script is the authoritative list of models labeled as reasoning-enhanced. Add to it when new reasoning models are tested. The `RUN_FILE_RE` and `CSV_FILE_RE` regexes define the expected filename patterns; adjust if your naming differs.

**Dependencies.** None (runs first).

### Script 1: `script_1_verbosity.py`

**Purpose.** Measures mean output-token counts per model from the `metrics.outputTokens` field in each run file. This is the first-line diagnostic for verbose-CoT context accumulation failures and a clean behavioral signature distinguishing reasoning from non-reasoning models on our benchmark.

**Inputs.**
- `--catalog <path>`: `run_catalog.csv` from Script 0.
- `--out-csv <path>`: where to write `verbosity_stats.csv`.
- `--out-fig <path>`: where to write `verbosity_distribution.png`.

**Outputs.**
- `verbosity_stats.csv`: one row per (model, task) with `output_tokens_mean`, `output_tokens_median`, `output_tokens_p90`, `output_tokens_max`, `cumulative_output_at_end`, `latency_ms_mean`, and `verbosity_index` (which is just `output_tokens_mean`, named for clarity in downstream scripts).
- `verbosity_distribution.png`: horizontal bar chart with one bar per model (averaged across tasks), colored by the three-bucket classifier (`terse`, `moderate`, `verbose CoT`) and with a dashed vertical reference line at 500 tokens.

**What it tells you.** If the figure shows a clean bimodal distribution — non-reasoning models clustered below 200 tokens, reasoning models clustered above 1000 tokens — that alone is publishable evidence that "reasoning model" is a measurable behavioral category on the benchmark. Moderate-bucket models may be partial reasoners or may have CoT sometimes suppressed by the JSON-only prompt; inspect their raw response text to decide.

**Dependencies.** Script 0.

### Script 2: `script_2_task11_metacog.py`

**Purpose.** Recomputes Task 11 metacognitive efficiency (MC = `d*` / `d_hat`) from the per-trial CSV with 95% bootstrap confidence intervals. The online run produces single-point estimates; this script adds statistical rigor by resampling and producing CIs on `d_hat`, type-2 AUC, and MC.

**How the math works.**
- `d_hat` uses standard type-1 SDT: `d_hat = Φ⁻¹(hit_rate) − Φ⁻¹(false_alarm_rate)`, with rates clipped to `(0.0001, 0.9999)` to avoid infinities.
- Type-2 AUC is computed by treating confidence as a threshold-varying classifier of the model's own correctness. The script sweeps over the sorted unique confidence values and integrates the resulting type-2 ROC by trapezoidal rule.
- `d*` is approximated from type-2 AUC via `d* ≈ Φ⁻¹(AUC) × √2`, which is the equal-variance Gaussian mapping. For the clean qualitative dissociation the paper claims, this approximation is sufficient. A full Maniscalco-Lau MLE estimation of `meta-d'` is a plausible future refinement — see [Extending the suite](#extending-the-suite).
- MC = `d*` / `d_hat`, with `NaN` when `d_hat ≤ 0`.
- Bootstrap: 2000 resamples by default, percentile method for the 95% CIs.

**Inputs.**
- `--catalog <path>`: `run_catalog.csv`.
- `--task-id <str>`: default `t11`; can be overridden to analyze a different task with the same SDT structure.
- `--n-boot <int>`: default 2000; reduce for faster iteration during development.
- `--out-csv <path>`: where to write `task11_metacognitive_efficiency.csv`.
- `--out-fig <path>`: where to write `d_hat_vs_type2auc.png`.

**Outputs.**
- `task11_metacognitive_efficiency.csv`: one row per model with `n_trials`, `hit_rate`, `fa_rate`, `d_hat`, `type2_auc`, `d_star`, `mc`, and all three 95% CIs.
- `d_hat_vs_type2auc.png`: scatter plot with `d_hat` on x, type-2 AUC on y, one point per model, with bootstrap error bars on both axes. A dashed horizontal line at y = 0.5 marks chance-level metacognition. Reasoning models are expected to cluster at high `d_hat` and y ≈ 0.5. Non-reasoning models should fall along the diagonal (higher `d_hat` correlates with higher type-2 AUC).

**What it tells you.** The published finding rests on this figure. If the paper's claim is correct, the reasoning models will form a distinct cluster in the upper-right-but-flat region of the scatter, and their bootstrap CIs on type-2 AUC will remain tight around 0.5.

**Dependencies.** Script 0.

**Expected CSV columns.** The `COLUMN_MAP` dict near the top of the script maps logical column names (`trial_type`, `is_correct`, `confidence`, `model_answer`) to actual column names in the CSV. Edit this if your Task 11 CSV uses different column names.

### Script 3: `script_3_task1_delegation.py`

**Purpose.** Computes per-model delegation rates in difficulty bins and plots delegation-rate-as-a-function-of-difficulty curves. A metacognitively functional model shows a positive slope (delegates more on hard items). A flat near-zero curve is the behavioral signature of a model whose routing signal carries no metacognitive information.

**Inputs.**
- `--catalog <path>`: `run_catalog.csv`.
- `--task-id <str>`: default `t01`.
- `--n-bins <int>`: default 5.
- `--out-csv <path>`: where to write `task1_delegation_curves.csv`.
- `--out-fig <path>`: where to write `delegation_by_difficulty.png`.

**Outputs.**
- `task1_delegation_curves.csv`: long-format CSV with one row per (model, difficulty bin). Columns: `model`, `diff_bin`, `n_questions`, `delegate_rate`, `answer_rate`, `mean_score`, `mean_difficulty`, `is_reasoning`.
- `task1_delegation_curves_slopes.csv`: wide-format CSV with one row per model and the fitted least-squares slope of delegation rate vs difficulty, plus the overall delegation rate.
- `delegation_by_difficulty.png`: line plot, one line per model, colored red for reasoning and blue for non-reasoning, dashed for reasoning and solid for non-reasoning.

**What it tells you.** If the reasoning-model hypothesis is right, the red lines will all cluster at or near y = 0 across the difficulty range, while the blue lines will show positive slopes. The slopes CSV turns that visual into a single number per model that can be fed into Script 5's convergence matrix.

**Dependencies.** Script 0.

**Expected CSV columns.** `difficulty`, `choice`, `score`, `question_id`. The script expects `choice` to be one of `ANSWER`, `DELEGATE`, or parse-fail-but-non-null. Parse failures are silently excluded from the delegation calculation.

### Script 4: `script_4_task2_coherence.py`

**Purpose.** Measures declared-vs-behavioral coherence on Task 2. The model produces both (a) declared MSV values on five dimensions and (b) a routing action (ANSWER / DELIBERATE / DELEGATE) per question. The script tests whether declared activation correlates with routing action in the direction expected if the self-report is metacognitively meaningful.

**Inputs.**
- `--catalog <path>`.
- `--task-id <str>`: default `t02`.
- `--out-csv <path>`: `task2_coherence.csv`.
- `--out-fig <path>`: `task2_coherence_scatter.png`.

**Outputs.**
- `task2_coherence.csv`: one row per model with `n_questions`, `activation_mean`, `activation_std`, `answer_rate`, `deliberate_rate`, `delegate_rate`, `activation_routing_corr` (Spearman), `corr_pvalue`.
- `task2_coherence_scatter.png`: small-multiples figure with one subplot per model. Each subplot shows declared activation on x and chosen routing action (coded ANSWER=0, DELIBERATE=1, DELEGATE=2, with y-jitter to make overlapping points visible) on y. A Spearman correlation appears in each subplot's title.

**What it tells you.** A reasoning model that produces differentiated self-reports but routes uniformly to ANSWER will show a flat horizontal band of points at y = 0 with near-zero Spearman correlation. A coherent model will show a positive-sloping cloud and a statistically significant positive correlation.

**Dependencies.** Script 0.

**Expected CSV columns.** `declared_activation` (or the five MSV columns `CE`, `ER`, `CI`, `EM`, `PI` from which activation is computed as their mean) and `routing_action` (string in `{ANSWER, DELIBERATE, DELEGATE}`). Adjust `ACTIVATION_COL`, `ROUTING_COL`, and `MSV_DIMENSION_COLS` at the top of the script if your column names differ.

### Script 5: `script_5_convergence.py`

**Purpose.** Integrates the outputs of Scripts 1–4 into a single convergence matrix with one row per model. Each row has the verbosity signal, three metacognitive signals, and a composite inefficiency score. The resulting heatmap is the most important figure for the NeurIPS paper because it lets a reader see the convergence at a glance.

**Inputs.**
- `--catalog <path>`: for the `is_reasoning` flag.
- `--verbosity-stats <path>`: `verbosity_stats.csv` from Script 1.
- `--task11-stats <path>`: `task11_metacognitive_efficiency.csv` from Script 2.
- `--task1-slopes <path>`: `task1_delegation_curves_slopes.csv` from Script 3.
- `--task2-coherence <path>`: `task2_coherence.csv` from Script 4.
- `--out-csv <path>`: `convergence_matrix.csv`.
- `--out-fig <path>`: `convergence_heatmap.png`.

**Outputs.**
- `convergence_matrix.csv`: one row per model, all signals joined, plus a `inefficiency_score` column (mean of three normalized signals, higher = more reasoning-model-like).
- `convergence_heatmap.png`: z-scored heatmap of the signals, rows sorted with reasoning models on top, a black horizontal line separating reasoning from non-reasoning rows, and original (non-z-scored) numeric values annotated in each cell for interpretability.

**How the composite score works.** For each of three signals (high verbosity, low Task 1 delegation slope, low Task 11 MC), values are min-max normalized to `[0, 1]` with the direction flipped where needed so that "more reasoning-like" always maps to 1. The inefficiency score is the mean of the three normalized signals. It is deliberately a simple unweighted mean to avoid leaking paper findings into the metric definition.

**What it tells you.** The heatmap is effectively the paper's core figure. If the red cells (high values) cluster in the reasoning-model block and the blue cells cluster in the non-reasoning block, the convergence argument is visually immediate. The annotated original values let readers read off each model's profile without having to mentally invert z-scores.

**Dependencies.** All of Scripts 1–4.

---

### Script 6: `script_6_verbosity_vs_efficiency.py`

**Purpose.** Tests whether verbose-CoT emission and metacognitive inefficiency are one phenomenon (common cause in reasoning-focused training) or two (separately measurable). Computes Pearson and Spearman correlations between verbosity index and each of the three metacognitive signals, and produces a three-panel scatter plot.

**Inputs.**
- `--convergence <path>`: `convergence_matrix.csv` from Script 5.
- `--out-csv <path>`: `verbosity_vs_efficiency.csv`.
- `--out-fig <path>`: `verbosity_vs_efficiency.png`.

**Outputs.**
- `verbosity_vs_efficiency.csv`: one row per metacognitive signal (`t11_mc`, `t01_delegate_slope`, `t02_coherence_corr`) with `n_models`, `pearson`, `pearson_p`, `spearman`, `spearman_p`.
- `verbosity_vs_efficiency.png`: three-panel scatter with `verbosity_index` on x and each metacognitive signal on y. Each point is annotated with its model name; reasoning models colored red, non-reasoning colored blue. Each panel's title shows the Pearson and Spearman correlations with p-values.

**What it tells you.**
- If verbosity shows strong negative correlation with all three metacognitive signals (more verbosity → worse metacognition), the paper can argue for a common cause.
- If the correlation is strong on one or two signals but weak on others, the phenomena partially dissociate and the paper should report that dissociation rather than overclaim a single common cause.
- If there are outliers (e.g., a non-reasoning model with low metacognitive efficiency, or a reasoning model with relatively high efficiency), they are individually worth discussing — the annotated scatter makes them immediately visible.

**Dependencies.** Script 5.

## Customizing for your data

Three customization points cover the most likely variations:

**1. Filename patterns.** Adjust `RUN_FILE_RE` and `CSV_FILE_RE` in `script_0_catalog.py` if your filenames differ. Test with a few sample filenames using the `re` module directly before running on the whole directory.

**2. Reasoning-model labels.** The authoritative list is `REASONING_MODELS` in `script_0_catalog.py`. Add model slugs as needed. The matching is exact string comparison, not substring, so `glm-5` and `glm-5-128k` would be treated separately.

**3. CSV column names.** Each script that consumes a CSV has a named column-map or constant near the top of the file:
- Script 2: `COLUMN_MAP` dict.
- Script 3: expects `difficulty`, `choice`, `score`, `question_id` directly.
- Script 4: `ACTIVATION_COL`, `ROUTING_COL`, `MSV_DIMENSION_COLS`.

Change these if your CSVs use different names. The scripts will print a clear error message naming the missing column if a rename is needed.

## Reading the outputs: what each figure means

For readers writing the NeurIPS paper, here is the natural narrative order of the figures:

1. **`verbosity_distribution.png`**: a behavioral signature exists. Reasoning models emit far more tokens than non-reasoning models on JSON-only prompts.
2. **`d_hat_vs_type2auc.png`**: object-level and metacognitive discrimination dissociate for reasoning models specifically.
3. **`delegation_by_difficulty.png`**: that dissociation shows up behaviorally too. Reasoning models do not adjust their routing to difficulty.
4. **`task2_coherence_scatter.png`**: the same dissociation shows up in declared self-reports. Reasoning models can describe uncertainty in structured self-reports without acting on it.
5. **`convergence_heatmap.png`**: the three signals agree. The reasoning-model block is visually distinct from the non-reasoning-model block across all three axes.
6. **`verbosity_vs_efficiency.png`**: the verbosity signature and the metacognitive inefficiency are correlated, suggesting a common cause in reasoning-focused training.

This ordering moves from observable (token counts) to derived (MC ratio) to synthetic (heatmap) to causal (verbosity-efficiency correlation). Readers build their mental model in that order naturally.

## Troubleshooting

**"No entries found" from Script 0.** Your filenames probably do not match the regex. Run `ls data/kaggle_runs/ | head -3` and check whether the names match the patterns in [Expected input filenames](#expected-input-filenames).

**"Skipping <model>: missing columns" from Script 2, 3, or 4.** The CSV for that model does not have the expected columns. See [Customizing for your data](#customizing-for-your-data) to update the column map, or inspect the CSV to understand what is different.

**NaN values in bootstrap CIs.** Script 2 skips bootstrap if fewer than 10 trials or fewer than 100 successful resamples are available. For small partial runs (e.g., 5–10 trials due to context-limit failures), the CIs will be NaN and only the point estimates will be trustworthy. Report the point estimate with a caveat about sample size.

**Heatmap looks washed out.** Script 5's heatmap uses a fixed color range of ±2.5 z-scores. If all your models are clustered, z-scores will be small and colors muted. Adjust `vmin`/`vmax` in `build_heatmap` for your data range.

**Script 6 correlations are NaN.** Need at least 3 models with valid values on both axes. If most of your reasoning models failed partway through, their metacognitive signals may be NaN, leaving too few data points. Run more models to completion or reduce the required minimum.

## Extending the suite

Three natural extensions would meaningfully strengthen the analysis:

**Full Maniscalco-Lau MLE `meta-d'`.** Script 2's approximation of `d*` from type-2 AUC assumes equal-variance Gaussian signals. The full Maniscalco-Lau framework estimates `meta-d'` by maximum likelihood over the 2×K contingency table of response-type × confidence-rating. Published ports exist in R (`metaSDT` package) and Python (several academic GitHub projects). Replacing `auc_to_d_star_approx` with an MLE call would upgrade the paper's claim from "approximate efficiency" to "literature-standard meta-d' efficiency."

**Per-question stratified analysis.** Rather than pooling all 80 Task 11 trials per model, stratify by question difficulty (from `gpqa_kaggle_candidates.csv`) and compute MC separately in easy / medium / hard bins. Reasoning models may show the dissociation most sharply on hard questions where the monitoring signal should matter most.

**Cross-run replication.** Each model should be run at least twice to compute run-to-run variance in MC and delegation slope. The current scripts only process one run per model. A small extension would aggregate across runs, report means and stds, and let the paper claim stability rather than single-run observations.

Each of these is a one- or two-day implementation. The current scripts produce the qualitative finding; the extensions produce the quantitative rigor needed for a top-tier venue.
